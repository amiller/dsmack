# macOS 27 App Attest code substitution — 2026-09-16

**Custody follow-up completed:** [persistent vs. memory-only experiment](custody/RESULTS.md)
finds that the tested Keychain item is readable by modified same-identity code.
A separate memory-only receiver requires fresh check-in after a forced process
restart to recover the same category key and decrypt stored ciphertext. This
updates the persistent-custody unknown below for that specific construction;
OS/kernel and forensic-memory attacks remain untested.

**Observed:** CDHash is authenticated in both enrollment and assertions on this
Mac. Modified code can reuse an existing App Attest key, but its assertions carry
the modified binary's hash. Enforcing the approved hash on every assertion rejects
the substitution. An app-identity/key-only policy accepts the same assertion.

This is a hardware evidence result, not a deployed membership adapter or a claim
about iOS. ST contract implementation remains deferred to a separate session.

## Test conditions

- Existing M4 Pro Mac mini; macOS 27.0 (26A428), Xcode 27 SDK.
- Two compiled variants of `Probe.swift`: honest operation returns 4; modified
  operation returns 5. Runtime JSON is diagnostic, not independently attested output.
- Same Apple Development credential, Team ID `DC9JH5DRMY`, bundle ID
  `dev.dsmack.provider`, bundle version 1, entitlement set, and active app path.
- Both variants use Hardened Runtime, omit `get-task-allow`, and pass strict
  `codesign` verification. The CDhash opt-in is present in the signed entitlements.
- Local `csrutil` checks report SIP and authenticated root enabled. More importantly,
  both enrollment certificates match Apple's exact documented Mac key ACL for
  SIP + Full Security. No platform security setting was changed.
- Six distinct verifier-generated challenges are saved next to captures. Key A is
  preserved across in-place binary replacement; key B is generated by modified code.
  Key ID files are public handles, not exported private keys.
- Isolated rig: `~/appattest-codebinding-20260916` on the Mac. The original probe and
  its captured evidence were preserved. The active test bundle ends on honest code.

## Verified outcomes

| Step | Authentic evidence | CDHash | Approved-code decision |
|---|---|---|---|
| Honest fresh enrollment, key A | Apple-rooted attestation, valid ACL | A | Accept |
| Honest assertion, key A | Valid signature, counter 1 | A | Accept |
| Modified app, reused key A | Valid signature, counter 2 | B | Reject |
| Modified fresh enrollment, key B | Apple-rooted attestation, valid ACL | B | Reject |
| Modified assertion, key B | Valid signature, counter 1 | B | Reject |
| Honest app restored, key A | Valid signature, counter 3 | A | Accept |

The replay independently verifies the modified assertion's signature under A's
enrolled public key before reporting its policy rejection. This distinguishes a
real measurement-policy rejection from an invalid signature or failed API call.
The raw assertion extension contains the current binary's digest, not A's original
enrollment digest. Removing the CDHash requirement makes the old-key attack pass.

## Verifier and evidence

`verifier/core.py` now supports an explicit SHA-256 CDHash allowlist and the exact
Mac ACL. It checks the pinned Apple root chain and validity, nonce DER structure,
credential/key/COSE binding, RP ID, environment, assertion signature and counter.
Absent or unsupported CDHash fields fail when a CDHash policy is selected.
The existing iOS service does not automatically become a Mac admission service:
the new policy is selected explicitly by the offline experiment.

The independently pinned root has DER SHA-256
`1cb9823ba28ba6ad2d33a006941de2ae4f513ef1d4e831b9f7e0fa7b6242c932`.
The older audit's original capture also passes these checks, including Mac ACL.
This fixes the demonstration's reliance on a supplied intermediate as a trust
anchor and its substring nonce check without changing that historical source.

The binary checker extracts the CodeDirectory and verifies its code-page hashes
against each captured Mach-O. Strict bundle validation was performed on the Mac;
the offline binary checker alone is not a full bundle-resource or CMS verifier.

## What remains open

- iOS 27 CDHash support and behavior: not tested.
- A genuinely independent developer team and signing credential: not tested.
- Reproducible source-to-CodeDirectory mapping across independently signed builds:
  not established by this two-variant experiment.
- Hostile-owner memory extraction, dynamic dependencies, persistent secret custody,
  and behavior after platform-security changes: not tested. CDHash evidence alone
  does not settle those properties or make an app equivalent to an enclave.
- Smart-contract adapter, faucet payout, per-device deduplication, and live category
  key release: not implemented here.

For an assertion-authorized operation, the verifier must bind that operation and
recipient to fresh client data and check the current CDHash. Enrollment-only code
checking is insufficient on the observed key lifecycle. This also does not retract
secrets already provisioned to an earlier approved execution.
