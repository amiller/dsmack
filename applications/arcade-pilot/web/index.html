Add search to Bounty Arcade’s board app.

Bounty Arcade is an existing public GitHub project containing small browser apps. Its Board app already lets you create, move, save, export and import cards in To do, Doing and Done columns. Issue #1 asks for a search box to find those cards.

This page offers a separately funded testnet bonus for that change. Dsmack is the runner and verification system used to check your patch and authorize its reward. The code you change lives in Bounty Arcade; you do not need to change Dsmack.

Submit your code, run the fixed browser checks on a Mac, and claim 0.0001 test ETH if the verified result qualifies.

A separate testnet bonus. The original three-judge bounty is unchanged.

What your change must do

Add a search box to the board. Search is case-insensitive and ignores surrounding whitespace: ' AP ' must match Apple, Grape and apricot, but hide Ship. Counts show matches/total while filtering. Clearing the search shows every card.

Filtering changes the view only. Saving and exporting must keep the entire board, including hidden cards. After reload, search is empty and all saved cards return.

Only your three board files are used: apps/board/index.html, logic.js and ui.js. They are applied to a fixed 39-file base; your package scripts, tests and other files are not run.

The seven fixed browser checks
  1. Add cards and wait for them to save.
  2. Find the search control.
  3. Match substrings across columns, ignoring case and surrounding spaces; show correct counts.
  4. Restore all cards and normal counts for a blank query.
  5. Export the full underlying board while filtered.
  6. Move the correct card while filtering.
  7. Reload with an empty search and the complete saved board.

The original baseline must fail a functional assertion; your candidate must pass all seven. A crash or infrastructure error does not count as the baseline failing correctly.

1. Register the commit you want checked

Push your change to a branch or PR reachable in amiller/bounty-arcade. Paste its full 40-character commit SHA—not a branch name, PR number or URL. This attempt keeps that exact commit and receiving wallet.

Your private key stays in your wallet. Registration asks you to sign an expiring message; it does not send a transaction or transfer ETH.

2. Run the checks

The same pinned checks and evidence requirements apply to both routes. A browser tab cannot launch your Mac by itself.

Ask a best-effort Mac

Queue this exact attempt for a registered node. You do not need a Mac or a coding-agent subscription. A node or completion time is not guaranteed.

Use your own Mac

Use the portable client on an Apple silicon Mac running macOS 27+, with trusted Python 3 and Node 24. Install the signed runtime and enroll your Mac through the public API.

Mac client instructions

Follow setup and enrollment instructions, then save this attempt file privately to the Mac. It contains your reconnect capability; do not post it.

What Dsmack does here

A peer contributes code. A Mac runs the pinned workload and retains App Attest execution evidence. An off-chain verifier checks that evidence, the fixed browser results and the delivered code, then signs an escrow decision. The smart contract checks those signatures; it does not verify Apple evidence itself.

This testnet pilot assumes a trusted execution host. It does not claim hostile-host tamper resistance.
