# Guest HTTP egress gateway

The guest-local gateway selects a measured hostname policy, opens HTTPS to that
name on port 443 and verifies its certificate and hostname. It enforces methods,
exact paths, byte budgets and request rates. Compute jobs use it for broker
inference; browser peers use its bounded WebSocket route for their tunnel.

Build and test from this directory:

```sh
go build -o gateway .
go test -race ./...
```

Run with a policy generated by the workload packer:

```sh
./gateway -policy /policy.json -http 127.0.0.1:8080 -dns '' \
  -upstream-proxy http://PROXY_IP:18443 -upstream-timeout 120s
```

Each rule sets `name`, `port: 443`, `methods`, exact `paths`,
`max_request_bytes`, `max_response_bytes`, `upload_bytes`, `download_bytes`,
`requests` and `requests_per_minute`. A name may be exact or a one-label wildcard,
for example `*.trycloudflare.com`. The application uses HTTP on port 8080 with
that hostname; the gateway authenticates upstream TLS before sending its request.
Only the measured endpoint is reachable through the compute node's CONNECT proxy.

A positive `websocket_seconds` enables WebSocket upgrades for that rule. The
browser peer starts the gateway with `-websocket-host TUNNEL_HOST`, which maps
loopback WebSocket requests to the measured TLS hostname. Each stream has a
lifetime and byte budget. HTTP body/header caps govern the upgrade request;
the opaque stream reserves the rule’s remaining `upload_bytes` and
`download_bytes`, then refunds unused bytes after closing. This carries model
transcripts larger than an ordinary HTTP body while retaining the measured
cumulative limits.

Optional `-dns :53 -answer-ip GATEWAY_IP` starts a non-recursive DNS stub. It
answers allowed A queries with that private address, returns no AAAA records
and refuses other names over UDP and TCP without forwarding them.

Budgets span connections for one gateway lifetime. Upload accounting includes
method, path, hostname, forwarded headers and body. Download accounting includes
upstream headers and body. Requests and upload bytes are charged before dialing;
unused reserved response bytes are returned. Redirects go back to the client for
a fresh policy check. Decision logs contain rule index, allow/deny, fixed reason
and byte counts; the guest seals them into the user's result channel.
