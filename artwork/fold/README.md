# Fold — porcelain and vermilion

Procedural artwork for the research NFT. The reissued main collection now
returns these images for the two existing participant tokens. The original
receipt contract remains text-only and continues to enforce admission and
account policy. See [main collection](../../release/main-collection.md).

![Gabe's participant token 2, rendered from its public identity](gabe-token-2.png)

## Design

One ceramic object, broad curved porcelain surfaces, rounded edges, a vermilion
glaze inside, and a restrained studio composition. Geometry is generated by code
and rendered with light transport; the output above is not image-generator output.
The earlier selected visual reference is in `reference-study.png` (Fold is the
left panel). That reference was generated with the built-in image tool; its exact
prompt is retained in `reference-prompt.txt`. The procedural version is an initial
interpretation, not a pixel match to the reference or a final quality approval.

The stable seed is SHA-256 of:

```
attest-fold-v1:<decimal chain ID>:<lowercase contract address>:<decimal token ID>
```

Only public identity fields enter the seed. Wallet keys, device identifiers,
clock time, claim verification flags, balance and live network activity do not.
The seed chooses six to eight folds, twist, aperture, angular orientation and a
small glaze-color variation. Material and lighting decisions belong to the
versioned renderer. This makes a coherent collection rather than unconstrained
random shapes. Traits are aesthetic; they do not imply rarity, trust, uptime,
independent signing or a unique human/device.

## Reproduce

Tested with Python 3.10 on Linux and Mitsuba's LLVM CPU renderer. Mitsuba requires
an available LLVM library and a writable compiler cache (`~/.drjit`).

```sh
python3.10 -m venv .venv-fold
.venv-fold/bin/pip install -r artwork/fold/requirements.txt
.venv-fold/bin/python -m unittest discover -s artwork/fold -v
.venv-fold/bin/python artwork/fold/render.py \
  --receipt release/friend-level1-receipt.json \
  --out build/fold-token-2 --size 1024 --spp 1024
```

Choose an unused output directory. It contains `fold.png`, public geometry meshes
and a manifest recording the seed, parameters, renderer source hash, dependency
versions and file hashes. The render is offline and does not verify the supplied
receipt. For ownership verification, run `scripts/release/verify_badge_receipt.py`
as documented in `release/acceptance-audit.md`.

Two separate 128×128 / 16-sample runs on this host produced identical PNG bytes
and mesh hashes. See `reproduction.json`. Geometry checks also cover finite,
nondegenerate surfaces and outward-facing skins across eight token identities.
Cross-platform pixel reproducibility has not been established; geometry identity
and image-byte identity are separate claims. The 1024×1024 image uses 1024 samples
per pixel and has its own `gabe-token-2-manifest.json`.

The mesh and material integration uses [Mitsuba's documented mesh loading](https://mitsuba.readthedocs.io/en/v3.5.0/src/how_to_guides/mesh_io_and_manipulation.html)
and [rough-plastic materials](https://mitsuba.readthedocs.io/en/v3.6.3/src/generated/plugins_bsdfs.html).
No third-party app executable or Darkbloom fixture is involved.

## Integration status

The main artwork collection is deployed; tokens 1 and 2 have their matching
images in metadata. Those two images are bundled in the Assembly Mac candidate.
Artwork for later participants still requires an explicit render, immutable
image publication, and artwork-registration/issuance transaction. The existing
publisher requires coordinated sponsor maintenance and transaction-journal
reconciliation; it is not a continuous or crash-resumable rendering worker.
Do not promise an immediate image to every new participant. Level 2 artwork and
its relationship to the parent receipt remain a design task.

The first full-size render completed, but its manifest attempt raced the default
asynchronous PNG save. The PNG and geometry were retained and checked; the
manifest was recovered from the matching successful small-render recipe. The
published renderer now writes synchronously. The full-size manifest records both
source hashes and the exact one-line reversal that reconstructs the capture
source. A small render after the fix matches the prior PNG byte for byte.
