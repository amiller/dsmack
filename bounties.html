Development bounties
verified with App Attest.

Someone funds a code change. A worker supplies a patch and runs the agreed checks on a Mac. A verifier checks the execution evidence, then signs a decision that lets the worker claim the reward from a smart contract.

The first pilot adds card search to Board, a small app in the public Bounty Arcade repository. A completed demonstration checked the patch and paid a Base Sepolia testnet reward to a controlled test wallet. App Attest evidence covers the checker run; the code was written separately.

How a code change earns the reward

The requester publishes the change and the checks a patch must pass, then deposits the reward into an escrow contract—a program that holds the money until its payment rules are satisfied. The worker submits a repository commit and runs the checker. Verification happens outside the blockchain; the contract checks the verifier’s signatures before allowing payment.

1. Define and fund

Off-chain · Creator / GitHub Publish the task

Name the repository, starting code, browser checks, reward and files the worker must deliver.

↓ Requester deposits the reward and records hashes of the task rules
On-chain · Smart contract Hold the reward

Hold the reward and record hashes of the rules. A hash identifies the exact file contents the parties agreed to use.

2. Do the work

Off-chain · Worker’s Mac Build and check a candidate

Run the agreed browser checks on the submitted code in a Linux VM. Save their results and the Mac app’s App Attest evidence.

No transaction needed while the work runs
On-chain · Smart contract Funds remain in escrow

The contract does not run the coding agent, browser or test suite.

3. Submit and claim

Off-chain · Submission Deliver code and result files

Submit the code commit and result files. The verifier compares their hashes with the task, checker and execution records.

↓ Submit the verifier’s signed decision for this task and result
On-chain · Smart contract Verify the decision and credit the worker

Check the required signatures and that they name the same task, assignment, worker address and result hashes. Record the worker’s credit; a separate withdrawal transaction transfers the reward.

In this pilot, verifier software checks the Apple evidence, execution records, browser results and delivered code outside the blockchain. Operator-controlled signing keys authorize the decision. The WorkEscrow contract checks those signatures; it does not itself verify Apple certificates or run the browser checks.

The worker’s checker run

The Board task asks for a search box that filters cards by a trimmed, case-insensitive substring. Searching for “ AP ” should show “Apple pie” and hide “Banana”. An empty search shows every card.

The seven browser checks also exercise saving cards, exporting the full board while a filter is active, moving the correct filtered card, and reloading with the search cleared. The tests are supplied separately from the candidate patch. The verifier checks the test program’s identity and reads its recorded results.

From a passing check to payment

A signed Mac app starts the Linux VM and signs statements about its inputs and returned files. The verifier checks Apple’s evidence and those signatures, then compares the recorded software and input hashes with the task’s expected files. It also reads the browser results to determine whether the patch passed.

A passing run is only part of the payment decision. The verifier checks the delivered code and worker address too. Its signed decision names the task and result; the contract prevents that decision from being used to pay a different worker or claim the same assignment again.

Try the testnet pilot

The public pilot lets a participant submit a Board code commit and follow the checker-and-claim process. The dashboard lists observed tasks, attempts and payments; the claim page handles an individual attempt. Check the displayed task and available reward before starting.

The completed demonstration used two real VM runs on the existing Mac mini: a self-run rehearsal and a funded worker run. Both passed the seven checks. The funded run withdrew 0.0001 Base Sepolia test ETH. That recorded payment is separate from the current availability of the public pilot. This prototype trusts the Mac’s host against tampering with VM storage.
