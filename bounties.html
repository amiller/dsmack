How the runner works Run a task on your Mac

The task, the execution and the escrow.

The repository, task instructions, code and execution stay off-chain. The contract holds funds and applies the settlement rules. The deployed pilot checks execution evidence off-chain and sends signed settlement decisions to the contract.

1. Define and fund

Off-chain · Creator / GitHub Publish the task

Repository and starting commit, acceptance code, environment, reward terms and delivery requirements.

↓ Creator transaction: funds + terms commitment
On-chain · Smart contract Hold the reward

Record the reward and a hash committing to the task’s settlement terms.

2. Do the work

Off-chain · Worker’s Mac Build and check a candidate

Run the pinned acceptance routine on the candidate. Retain result files and App Attest execution evidence.

No transaction needed while the work runs
On-chain · Smart contract Funds remain in escrow

The contract does not run the coding agent, browser or test suite.

3. Submit and claim

Off-chain · Submission Deliver code and result files

Publish or deliver the candidate and the required artifacts. Evidence binds them to the task and its checker.

↓ Resolve transaction: signed decision + task / result bindings
On-chain · Smart contract Verify the decision and credit the worker

Verify the selected execution, review and delivery roles’ signatures over the task, assignment, payee and result commitments. Credit the worker; withdrawal transfers the reward.

The Base Sepolia pilot uses WorkEscrow with a trusted EOA verifier bridge. The bridge checks Apple and runtime evidence, acceptance and delivery off-chain. WorkEscrow verifies the signed decision and credits the assigned payee. Full source and result files remain off-chain.

The worker’s checker run

A signed Mac app boots a reusable Linux VM. Inside it, a selected container runs the coding agent or acceptance routine. Separate inputs identify the task and candidate; separate outputs retain the results.

The app produces launch and result assertions. A verifier checks the original evidence against the expected app, base image, workload and task bindings.

A bound settlement decision

App Attest authenticates the app’s key and assertions. The task’s pinned acceptance routine defines success. The contract’s verification rules must bind that passing result to this task and the worker being paid, and reject replay.

Apple authenticates the app-key evidence. The acceptance routine checks the patch. The verifier bridge binds the passing result to the task and the worker’s settlement decision.
