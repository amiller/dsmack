A release should answer what it does, what it can access, and which checks support those claims—before asking for a credential or a VM launch.

First, identify the product.

The public repository currently contains the earlier measured runner and App Attest components. The new generic libkrun/HVF runner, participant client and alpha staging work are unpublished candidates. A public GitHub commit or the old Node download is not the new alpha release.

The agent's review packet

Ask for these public materials together. A checksum supplied only by the untrusted download cannot select its own authority.

  1. Release identity: immutable version, exact archive size/hash, detached inventory signature, externally selected root, validity window and rollback policy.
  2. Source correspondence: selected source commit, native/helper inventories, build inputs and output records. A maintainer build or packaging attestation must not be described as a reproducible hosted source build.
  3. Actual Mac identity: full CodeDirectory SHA-256, Team/bundle, Developer ID leaf certificate, complete entitlements and provisioning profile. Check code pages, Apple signature and bundle resources separately.
  4. Distribution checks: actual stapled-ticket validation and macOS distribution assessment for the final exported app. Export/re-signing can change its code hash; enrollment must use that final identity.
  5. Workload plan: selected Linux base and OCI digests, file inputs, mounts, writable paths, network destinations and finite resource/time limits.
  6. Disclosure and recovery: what remains local, what reaches a provider/verifier, persistent enrollment keys, progress freshness, retained evidence and how to inspect an interrupted run without launching twice.

Cheap checks before expensive work.

Begin with a read-only inventory of OS/version, architecture, available memory and disk, required tools and release files. The current doctor reports these observations; it does not test the VM or declare launch readiness.

Next, authenticate and privately stage the selected release, check the actual signed app, then perform a disclosed fresh enrollment and bounded credential-free sample. Inspect the original verified result before considering a subscription-backed task.

Do not copy your whole Claude/Codex home, hooks, MCP configuration, SSH keys, browser profile or history. Import only fields explicitly allowed by a separately reviewed recipe.

Known limits of this checkpoint

  • The new alpha package and runtime admission journey are not publicly available yet.
  • The qualification Mac had global Gatekeeper assessments disabled. Direct signature, stapler and distribution checks passed; a quarantined fresh-Mac open remains unqualified.
  • App Attest's fraud receipt is retained but not validated by the current verifier.
  • The pilot trusts the host; it does not protect private staging or disks from root.
  • Progress can be stale. Closing a tab or terminal is not confirmation that a VM stopped.
