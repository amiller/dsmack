Mac alpha · Credential-free starter

Run a task on your Mac.

Install the signed runner, run a small browser task inside its Linux VM, and keep the original execution evidence. This starter needs no coding-agent subscription or payment.

You need an Apple silicon Mac running macOS 27.0 or later, Python 3, a trusted Node 24 runtime, and at least 32 GiB of free disk space for download, installation and working disks.

1. Download and extract the runtime.

From the runner-v0.1.0-alpha.1 release, download dsmack-runner-macos-arm64-alpha.1.zip (about 869 MB). Extract it into a folder you own. The optional source-offer archives are separate; you do not need them to run the starter.

Open Terminal in the extracted folder containing FRIEND-START-HERE.txt, release-public.pem and source/. All commands below start in that folder. Read FRIEND-START-HERE.txt and source/docs/pilot/friend-invitation.md; the bundled source is commit b068448d7983d67b827ced6d7286c7f4fc9252e7.

pwd
ls FRIEND-START-HERE.txt release-public.pem source/README.md
python3 --version
node --version

The last command must report Node 24. On macOS, bootstrap retains your existing Node executable and loaded-library paths. That executable, its non-system libraries, the inspected bootstrap source and their ancestor directories must be protected against group/other writes; dependencies must have ordinary, single-link files. A copied Homebrew executable alone is not a standalone runtime. Bootstrap installs no dependencies and refuses unsafe or injected runtimes. Follow source/docs/pilot/alpha-install.md if your prerequisite is refused.

2. Confirm the release key.

Check this public-key fingerprint through an independent maintainer channel before trusting the download. A checksum index inside the same ZIP cannot establish its own authority.

shasum -a 256 release-public.pem

Expected SHA-256:

4de4686cb585a54375a9ab859aa533e8a81255d9d2c9a76b96d0ae9006ecc0df

The following steps use that key to authenticate the detached release signature. Keep macOS security settings enabled; this procedure does not require re-signing the app or removing quarantine.

3. Create your local bootstrap.

Run once with fresh destination paths. This records your Mac's selected Node runtime and copies the small authenticated-staging tools into a private directory.

umask 077
mkdir -m700 "$HOME/.dsmack-friend"
node source/applications/pilot-client/alpha-bootstrap.mjs \
  --trust-key "$PWD/release-public.pem" \
  --key-id dsmack-alpha-20261022-86473863 --channel alpha \
  --min-sequence 28 --out "$HOME/.dsmack-friend/bootstrap"

Expected result: JSON naming bootstrap.json and alpha_stage.py, with launch_ready: false. The runner is not installed or launched yet.

4. Check the plan, then install.

First authenticate the inventory and inspect the reported sizes without creating an installation:

python3 -I "$HOME/.dsmack-friend/bootstrap/alpha_stage.py" \
  --bootstrap "$HOME/.dsmack-friend/bootstrap/bootstrap.json" \
  --inventory "$PWD/release-starter-friend-r1.UNSIGNED.json" \
  --signature "$PWD/release-starter-friend-r1.sig" \
  --target "$HOME/.dsmack-friend/runtime" --plan

Then install the exact signed archive:

python3 -I "$HOME/.dsmack-friend/bootstrap/alpha_stage.py" \
  --bootstrap "$HOME/.dsmack-friend/bootstrap/bootstrap.json" \
  --inventory "$PWD/release-starter-friend-r1.UNSIGNED.json" \
  --signature "$PWD/release-starter-friend-r1.sig" \
  --archive "$PWD/release-starter-friend-r1.tar.gz" \
  --target "$HOME/.dsmack-friend/runtime"

.UNSIGNED.json is the canonical document's filename; its .sig is the detached signature. Installation authenticates and stages the runtime, but still reports launch_ready: false. If a command refuses or leaves a partial installation, preserve its output and paths for diagnosis rather than overwriting them or resetting rollback state.

5. Obtain a task for this Mac.

The current download does not include a reusable invitation. At this step, the alpha operator checks your Mac's fresh enrollment and supplies an admitted local task, invitation.json, and its independently communicated SHA-256 digest. Use the exchange described in source/docs/pilot/operator-assisted-mac.md; there is no public signup or enrollment endpoint in this release. This is the current tooling handoff, not a protocol requirement for human approval of every task.

Keep the supplied files at their specified local paths. Put the actual invitation in this working folder, then replace OPERATOR_DIGEST below with its digest. Inspect the selected app, base, workload, paths and finite resource limits before preparing the run.

python3 -I source/applications/pilot-client/friend.py inspect "$PWD/invitation.json" --sha256 OPERATOR_DIGEST
python3 -I source/applications/pilot-client/friend.py prepare "$PWD/invitation.json" --sha256 OPERATOR_DIGEST
python3 -I source/applications/pilot-client/friend.py check "$PWD/invitation.json" --sha256 OPERATOR_DIGEST

These commands inspect the invitation, prepare its local plan and run admission checks. They do not start the VM. Stop here if a check refuses.

6. Run once and retain the result.

python3 -I source/applications/pilot-client/friend.py run "$PWD/invitation.json" --sha256 OPERATOR_DIGEST

The runner launches the selected Linux VM and retains its result. For an interrupted terminal or a status check, use the same invitation:

python3 -I source/applications/pilot-client/friend.py resume "$PWD/invitation.json" --sha256 OPERATOR_DIGEST

resume observes an attempted run; it does not implicitly launch it again. Preserve the complete original output directory and friend-summary-NATIVE_ID.json. The summary is useful status, not cryptographic proof. Closing Terminal does not confirm that a VM stopped.

7. Have the original evidence checked.

Provide the retained originals through the operator's agreed evidence-transfer route. The selected Linux x86-64 verifier checks the launch and result assertions, output bytes and expected workload outcome. Full verification currently uses that qualified Linux environment; there is no equivalent self-service Mac command in this guide.

The published starter qualification passed full hardware verification and its fixed 14-test fixture, including 80 admitted logic cases and retained screenshots, videos and traces. Your run needs its own verification result. This diagnostic starter does not submit a bounty or earn a reward.

Once evidence is preserved and the owned VM/helper is confirmed stopped, coordinate cleanup of disposable scratch disks and staged public copies. Retain the proof originals; do not delete uncertain state. A normally secured fresh-Mac first-open remains unqualified by the published test, so retain any macOS refusal for diagnosis.
