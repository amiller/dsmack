Mac alpha · Browser-test starter

Run a task on your Mac.

Install DsmackRunner, the signed macOS app, together with its Linux image and client scripts. Run a fixed browser-test fixture in the VM and save the test results and signed execution records. You need no coding-agent subscription or payment for this starter.

You need an Apple silicon Mac running macOS 27.0 or later, Python 3, Node.js 24, and at least 32 GiB of free disk space for download, installation and working disks.

Arrange the task handoff with an alpha operator before installing. This release needs the operator to check your Mac’s App Attest registration, send the task files in step 5, and verify the returned evidence in step 7.

1. Download the app, Linux image and scripts.

From the runner-v0.1.0-alpha.1 release, download dsmack-runner-macos-arm64-alpha.1.zip (about 869 MB). Extract it into a folder you own. The optional source-offer archives are separate; you do not need them to run the starter.

Open Terminal in the extracted folder containing FRIEND-START-HERE.txt, release-public.pem and source/. All commands below start in that folder. Read FRIEND-START-HERE.txt and source/docs/pilot/friend-invitation.md; the bundled source is commit b068448d7983d67b827ced6d7286c7f4fc9252e7.

pwd
ls FRIEND-START-HERE.txt release-public.pem source/README.md
python3 --version
node --version

pwd shows the folder you are using; ls confirms the expected release files are there. Check that Python is version 3 and Node is version 24 before continuing.

The next step records the Node executable and libraries already on your Mac. Other users and groups must not be able to modify those files, the setup source or their parent directories. Dependency files must be ordinary files with one hard link. Copying a Homebrew Node executable by itself is insufficient because its libraries may still be elsewhere. The setup tool installs no dependencies and rejects unsafe permissions or injected runtimes. If it refuses your Node installation, keep the error and follow source/docs/pilot/alpha-install.md.

2. Confirm the release key.

The release signature tells you whether the files were approved by the holder of this key. First confirm the key’s SHA-256 fingerprint with the maintainer through a separate trusted channel. Comparing files only with checksums from the same download would not establish who supplied them.

shasum -a 256 release-public.pem

Expected SHA-256:

4de4686cb585a54375a9ab859aa533e8a81255d9d2c9a76b96d0ae9006ecc0df

The following steps use that key to authenticate the detached release signature. Keep macOS security settings enabled; this procedure does not require re-signing the app or removing quarantine.

3. Record your local tools and release key.

This command creates a private folder for your setup files. It records the release key you checked, the minimum release sequence to accept and the local Node files needed by the installer. It also copies the installer into that folder. The resulting bootstrap.json is a local configuration file; it is not a VM image. Use fresh destination paths and run this step once.

umask 077
mkdir -m700 "$HOME/.dsmack-friend"
node source/applications/pilot-client/alpha-bootstrap.mjs \
  --trust-key "$PWD/release-public.pem" \
  --key-id dsmack-alpha-20261022-86473863 --channel alpha \
  --min-sequence 28 --out "$HOME/.dsmack-friend/bootstrap"

The command prints JSON with the paths to bootstrap.json and the installer, alpha_stage.py. launch_ready: false is expected: you have recorded the local tools, but have not installed the runner or prepared a task.

4. Check the release contents, then install.

The inventory is the JSON list of release files, their sizes and their hashes. The first command checks its signature using your saved key and shows the installation plan and sizes. --plan leaves the runtime uninstalled, so you can inspect the result before continuing.

python3 -I "$HOME/.dsmack-friend/bootstrap/alpha_stage.py" \
  --bootstrap "$HOME/.dsmack-friend/bootstrap/bootstrap.json" \
  --inventory "$PWD/release-starter-friend-r1.UNSIGNED.json" \
  --signature "$PWD/release-starter-friend-r1.sig" \
  --target "$HOME/.dsmack-friend/runtime" --plan

If that check succeeds, run the installer with the archive. It checks the archive against the signed file list and writes the runtime into $HOME/.dsmack-friend/runtime.

python3 -I "$HOME/.dsmack-friend/bootstrap/alpha_stage.py" \
  --bootstrap "$HOME/.dsmack-friend/bootstrap/bootstrap.json" \
  --inventory "$PWD/release-starter-friend-r1.UNSIGNED.json" \
  --signature "$PWD/release-starter-friend-r1.sig" \
  --archive "$PWD/release-starter-friend-r1.tar.gz" \
  --target "$HOME/.dsmack-friend/runtime"

The filename contains .UNSIGNED.json, but the separate .sig file supplies its signature. A successful installation still reports launch_ready: false: the runtime is installed, but no task is ready to launch. If either command refuses or leaves a partial installation, keep its output and the affected paths for diagnosis. Do not overwrite the partial files or reset the installer’s record of previously accepted release sequences.

5. Obtain a task for this Mac.

You now need help from the alpha operator. Follow source/docs/pilot/operator-assisted-mac.md to register a fresh App Attest key from your Mac. The operator checks that registration and supplies task files prepared for this Mac, an invitation.json describing them, and the invitation’s SHA-256 digest through the agreed channel. This starter release has no public signup or enrollment endpoint, and its download does not include an invitation you can reuse.

Keep the supplied files at the paths named in the invitation. Put invitation.json in the working folder and replace OPERATOR_DIGEST below with the digest the operator sent. Read the inspect output: it identifies the Mac app, Linux image, task files, local paths and resource limits you are about to use.

python3 -I source/applications/pilot-client/friend.py inspect "$PWD/invitation.json" --sha256 OPERATOR_DIGEST
python3 -I source/applications/pilot-client/friend.py prepare "$PWD/invitation.json" --sha256 OPERATOR_DIGEST
python3 -I source/applications/pilot-client/friend.py check "$PWD/invitation.json" --sha256 OPERATOR_DIGEST

inspect checks the invitation and shows its contents. prepare writes the local run plan from those exact files. check verifies that the plan and files meet the runner’s requirements. None of these commands starts the VM. Continue only if all three succeed; keep any refusal message for the operator.

6. Run once and retain the result.

python3 -I source/applications/pilot-client/friend.py run "$PWD/invitation.json" --sha256 OPERATOR_DIGEST

run starts the Linux VM for this task and saves its execution records and result. If your terminal is interrupted, or you want to inspect the run’s status, use resume with the same invitation:

python3 -I source/applications/pilot-client/friend.py resume "$PWD/invitation.json" --sha256 OPERATOR_DIGEST

resume reports on the existing attempt rather than launching another VM. Keep the entire original output directory and friend-summary-NATIVE_ID.json. The summary tells you what the tools observed; the original files are needed to verify the execution. Closing Terminal alone does not establish that the VM has stopped.

7. Have the original evidence checked.

Send the retained original files through the evidence-transfer route agreed with the operator. The operator runs the tested verifier in Linux x86-64 to check the app’s App Attest launch and result assertions, the output bytes and the task’s expected outcome. Ask for that verification result before treating the run as checked. This guide does not provide an equivalent self-service Mac verification command.

The published test of this starter passed full hardware verification and its fixed 14-test fixture, including 80 predefined logic cases. Screenshots, videos and traces were retained for that test. Your Mac’s run still needs its own verification result. Running this diagnostic starter does not submit a bounty or earn a reward.

After the originals are safely preserved, confirm with the operator that this run’s VM and helper have stopped. Then remove its disposable scratch disks and temporary public input copies through the agreed cleanup procedure. Keep the proof originals and any state whose purpose is uncertain.

The published test did not establish that first launch works on a different, normally secured fresh Mac. Keep macOS security settings enabled and retain any first-open refusal for diagnosis.
