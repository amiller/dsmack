Dsmack is a protocol for verifying Apple App Attest evidence across developer accounts. An application can recognize approved code on someone else’s Mac, including copies signed by other developers.

What is App Attest?

App Attest lets a recipient verify that a signed message came from a particular app on genuine Apple hardware.

Dsmack uses it for records of a task run: which software and input files were used, and what results came back. A requester can check those records against the task’s requirements, even when someone else operates the Mac.

Apple designed App Attest for an app developer’s server to recognize its own app. Dsmack makes these checks available to peers and smart contracts, including apps signed under different developer accounts.

How can different developer accounts run the same approved code?

Apple’s evidence includes the app’s identity and a hash of its signed code directory, called its CDHash. Signing the same program under another developer account changes that identity and hash.

Dsmack’s code registry compares a measurement of the program that leaves out specified account and signing fields while retaining the code pages and specified security settings. Another developer can register a renamed, re-signed copy of an approved build by showing that this measurement matches. The verifier still checks the copy’s App Attest identity and CDHash.

Applications decide which program measurements to accept. That decision can be recorded in a public smart contract, so participants can inspect the same list of approved code.

Check the certificates in Solidity

Smart contracts verify Apple’s certificate signatures and store the app’s public key. Later transactions check messages signed by that key.

Prove the certificate checks were performed

A computer runs the certificate checks and produces a zero-knowledge proof that the required calculations passed. A contract verifies that proof instead of repeating all those calculations. It then checks the app’s later signed messages.

How a task runs on the Mac

A signed macOS app starts a Linux virtual machine and signs statements about its launch and result. Linux runs the task in a container: a package containing the program and its dependencies.

DsmackRunner · the signed macOS app

Checks boot and task files against expected hashes, starts Linux, and signs the execution records after the VM stops.

Reusable Linux VM image

Linux, Docker, and a supervisor program that starts the task and collects its outputs.

Task container · supplied for this application

The task specifies the container image, command, input files, memory limit and network permissions.

Coding agentBrowser / CI tests

Returns output files and a result record.

A browser checker and a coding agent can use the same Linux image, with their tools in different containers. Scripts on the Mac prepare the task files. The app checks their hashes, runs the task, and signs the execution records. The recipient compares those records and outputs with its original request.
