App Attest for
permissionless applications.

Dsmack is a protocol and policy for checking Apple App Attest evidence without depending on a particular developer account.

Its reference implementation includes zero-knowledge proofs and Solidity verifiers. Applications can use shared verification rules to accept evidence from independently operated Macs.

Verification rules applications can share.

The application chooses its admission policy: accepted code and app identities, the execution context and the result bindings. The verifier checks Apple’s evidence against that policy.

Direct Solidity verification

The contracts check the Apple certificate chain, attested app key and assertions. An application can enforce the resulting evidence in its own protocol.

Zero-knowledge verification

A proof establishes the attestation-leaf checks. The Solidity adapter checks the proof’s public values against the same policy, then verifies subsequent assertions.

Evidence binds the run to the application.

1 · SELECT

Fix the expected inputs

The verifier’s context names the admitted app and runtime, workload and input commitments, a fresh challenge and the application’s result rules.

2 · EXECUTE

Retain two assertions

The Mac app creates a launch assertion and a result assertion. Their signed digests bind the challenge and execution statements, including the selected inputs and returned result envelope.

3 · VERIFY

Check the original evidence

The verifier checks Apple’s app-key attestation, assertion signatures and counters, expected identities and result hashes. The application’s checks determine whether the result is acceptable.

App Attest authenticates the app key and assertions. The selected runner and runtime policy define the execution statements being relied on.

Operators run the application. Verifiers apply its rules.

Enrollment establishes an app key. Fresh challenges and assertion counters bind each subsequent run. The application’s acceptance checks determine whether the returned result qualifies for its service or settlement action.

The current execution prototype uses an experimental trusted-host policy. The bounty pilot checks Apple and runtime evidence off-chain, while the reference App Attest contracts demonstrate direct and ZK verification on-chain.
