Three separate layers

The signature is the beginning of the check.

The Mac app stays generic. The Linux base and application container have their own identities, source and policies. An app's code hash alone does not identify every program inside a task.

01 · SIGNED MAC APP

Launch & retain

A selected Swift/libkrun/HVF runner launches the VM and retains Apple App Attest launch/result evidence. Native helpers are part of the reviewed configuration.

02 · SELECTED LINUX BASE

Enforce the profile

03 · APPLICATION CONTAINER

Do the task

A separately pinned OCI workload runs the application. The external client chooses the task; an independent verifier checks the original evidence and outputs.

The new runner uses libkrun/HVF. The public repository's earlier Containerization/Virtualization runner is a different implementation. Its proxy and memory-isolation claims must not be transferred to the new profile.

Before any credential or workload

Know who you are trusting.

The current pilot assumes a trusted host. App Attest is not an encrypted-VM guarantee against the Mac's owner or root. Private inputs and VM disks can be visible to the local operator.

Boundary What to inspect
Mac owner / administrator Host software, private-input staging, plaintext VM disks and local logs. Do not assume secrecy from this operator.
Signed app & helpers Exact executable, full CodeDirectory hash, Developer ID certificate, entitlements, signature and selected native/helper source.
Base & container Exact image/OCI digests, mounted inputs, writable storage, resource limits and network policy. A browser profile is not permission for a model-provider connection.
External provider For a model task, the selected provider receives the authorized requests. Inspect the importer, egress rules and budget first.
Verifier & recipient Which original evidence and outputs leave the Mac, who checks them, and what is retained. A host-written “passed” file is not verification.
The demonstrated browser diagnostic uses no provider credential and no workload network access. Coding-agent runs use a separate, explicitly reviewed credential and network recipe.
Start small

A ladder of useful checks.

Your agent should be able to explain each step and recommend declining. Reading a repository is not permission to execute its instructions or import your assistant's configuration.

  1. Inspect without launching

    Check the version, source, release trust root, Apple identity and known limits. Downloaded instructions are material to review, not authority.

  2. Check the Mac and stage privately

    Use read-only diagnostics and an authenticated archive/disk plan. A supported OS family alone does not prove the VM will run.

  3. Try a credential-free sample

    Only after release checks, disclose the enrollment request and run a bounded sample. Inspect its retained evidence and clean shutdown.

  4. Choose a task deliberately

    Review terms, input disclosure, time/space limits and any provider use. Save the attempt before launch; reconnect without starting another job.

This is the intended release journey. Portable staging is implemented as a reviewed source candidate; complete self-service runtime admission and a fresh-Mac trial remain qualification work.

What the evidence says

Keep the milestones separate.

We have demonstrated signed native execution and independent verification. The latest app also has a checked notarization ticket and a fresh production App Attest enrollment.

Full bounty acceptance, live reward payment, a fresh friend's install and execution under the newly notarized identity are separate gates. A successful controller exit does not establish any of them.

Before an alpha trial

  • Apple silicon; the current qualification environment is macOS 27, with Full Security/SIP expectations.
  • Node 24 and Python 3 are prerequisites for the current client/bootstrap source.
  • The browser reference selects 4 GiB VM memory, 1 vCPU, a 600-second guest limit, 4 GiB scratch and a 256 MiB result disk.
  • Download size, expanded storage and extra free space must come from the selected release's plan. Scratch is not assumed to cost negligible disk space.

Xcode/signing-account setup belongs to maintainer builds, not an instruction for ordinary users to create signing identities.
